# 家庭找物

需要读写家庭档案时，使用用户提供或选择的本地档案文件夹；不要假定某个云盘、知识库或个人目录。先检查该文件夹里的现有档案，保持原始人工编辑和历次记录。找不到唯一档案时先核实路径，避免新建平行档案。首次建档时，按 [第一次使用](references/first-use.md) 操作：用户选定文件夹并要求初始化后，可在其中准备空档案；本 Skill 的 CLI 不提供初始化命令。

用本 Skill 目录下的 `scripts/home_finder.py`，调用形式为 `python3 脚本绝对路径 --catalog 档案绝对路径 子命令`。档案、导出页面和用户选择保存的家庭附件留在该本地文件夹；不要把私人档案或照片复制进 Skill 目录。

## 第一次使用

用户问「第一次使用」「怎么拍」「怎么录视频」「怎么用」，或要初始化一个新家庭时，先读 [第一次使用](references/first-use.md)。首次使用默认按整个房间进行，房间尚未明确时直接问「你想先录哪个房间？厨房、卧室，还是其他房间？」用户已说清房间时直接继续，不主动让用户改选柜体或抽屉。用户主动只提供局部时，如实记录在对应房间下。用户提供整个房间时录入其中能确认的全部物品或分组，并交付带「按房间浏览」卡片模块的主导览页，只有一个房间也显示卡片。首次使用引导在查档和写入前就可以提供。已有家庭档案时继续使用当前档案；缺少档案或未指定新家庭保存位置时，先处理确实需要的定位信息。

## 找物

1. 用 `find "用户的说法"` 查名称或别名。命中多项、只命中泛称或查不到时，用 `list --summary` 结合已记录特征筛选，明确候选后用 `find ID --by-id` 核对位置与照片。抽象描述、身份歧义和无记录时在聊天里协助判断。
2. **只要确认了具体物品并要指路，交付必须是可点击的本地 HTML 物品路线。** 读 [HTML 导览](references/html-guide.md)，打开最新页面的物品入口，聊天留一句结果和入口链接。用户明确要求文本或照片时按其要求另给。页面应区分位置参照、可辨物品照和口述记录。
3. 名称、别名、类别、颜色或收纳位置等关键词可以直接在 HTML 里搜。查某柜或层时链接到相应搜索结果。只有用户确认了新叫法或新物品，并有依据时，才更新档案与 HTML；单次推测与待补候选留在聊天或本机候选。

## 失物回溯

明确说原处没有、物品未归位后找不到、怀疑丢了，或要求按动线找时，先读 [失物回溯](references/retrace.md)。已入档的位置只作为带日期的旧线索；已排查的旧位置不再当作当前指路。未入档物品也可以直接按用户实际见过和做过的事继续，有已知相关录像时只回查需要的片段。线索够时立即给少量待查点，线索不足时只问最能缩小范围的一件事。查找中的推测和排查状态不写进家庭物品档案。

## 录入或移位

- 用户提供新材料时读取 [录入与证据](references/intake.md)，按已知房间与柜体增量录入。通过 `add --batch 候选JSON --backup-dir 本地备份目录` 采用新条目，采用前核对重复、层号和照片。
- 在某处找到物品属于发现事实；用户说明仍放原来的固定位置时，沿用固定记录。只有用户确实报告了物品的移动且对象与目标唯一时，从当前档案取物品 ID 和旧位置 ID，执行 `move --id 物品ID --from 旧位置ID --to 目标位置ID --at YYYY-MM-DD --detail 具体位置 --backup-dir 本地备份目录 --note 原口述`。新地点加 `--new-path '房间/柜体/收纳层'` 与一个或多个 `--step '指路步骤'`。只写用户已明确的细节；新位置从用户口述建立，旧照片随历史保存。搬动和查询含义不清时，只询问缺失的身份或新地点。
- “如果移到”“试一下搬走”属于演练。复制档案到同一任务的本地运行目录，复制所需相对附件或在本地保留同结构，再测试；正式位置只接受真实搬动指令。
- 写入前按工作区的本地运行合同选任务目录并备份；写入后用 `check` 和一次查询核对，再按 [HTML 导览](references/html-guide.md) 从同一份档案重新导出受影响页面，交付新路线或搜索入口。用户提出可复用的新规则时更新同目录原需求文档，区分已验证行为和待做功能。
