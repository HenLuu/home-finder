# 录入与证据

按原片时间识别位置变化，以“能认地点的外观”和“能认目标的内部”配对。原视频若可在本机读取，先用现有视频工具抽取带时间点的清晰帧。可以用 FFmpeg 按时间截图；有本机语音识别工具时提取音轨转写，以原片时间对齐。没有转写时仍可根据可见画面录入；模糊品名和拍不到的位置请用户补确认。家庭素材外发给识别服务须有针对该素材与服务的授权。

先从工作区运行目录做候选。临近位置只有视觉相似不足以合并；跟随从外观、开门到内部的顺序，或用明确旁白建立同一位置关系。层号以视频可确认的顺序为准，抽屉关系不明确时只到柜区。旁白口述能支持名称和位置，但对应画面只能看出容器时，把照片标成区域参照。选定的证据帧存入档案目录的 `附件/`，用源片标识和时间命名，避免重名和无关元数据。原片及草稿留在原位置和本地运行目录。

## 增量批次

先用 `list --summary` 检查现有 ID、名称、别名和收纳区。候选批次与档案采用相同的顶层结构：

- `schema_version` 为 1。
- `sources` 以稳定来源 ID 为键，值含 `file` 和 `recorded_at`。原片可原位保留。
- `locations` 以地点 ID 为键，含从房间开始的 `path`、简明 `steps` 和 `photos`。每张照片是 `file`、`at`、`label`，`file` 相对档案目录。地点照片描述柜门、层或抽屉等参照。
- `items` 是物品列表。每项含 `id`、`name`、`aliases`、`location`、`detail`、`recorded_at`、`evidence`、`history`。新条目的历史为空列表。别名用实际用途或常用说法，通用词若有多项应保留歧义。
- `evidence` 含 `kind`、`source`、`at`、`photos`、`note`。`kind` 用 `visual`、`spoken`、`visual+spoken` 或 `user_report`。视频类证据引用来源 ID；新口述可以 `source: null`，没有实拍时照片为空，`note` 留已提供的定位证据。时间点记录在 `at`，相对位置和可见性写在 `detail` 与 `note`。
 
对既有条目补别名或证据时核对物品 ID、保留原记录和人工编辑，备份后对当前文件做最小修改并运行 `check`。物品搬动统一走 `move`，无需重新录同一物品。无把握的候选留在本地核对材料里。

提交首批和后续增量时，把授权素材内能确认的条目导出到同一 [HTML 导览](html-guide.md)。路径或物品身份仍缺依据的内容留在本机候选，待补齐后再进入搜索。颜色属于物品本体、包装或部件时记录清楚，旁边参照物的颜色不当作目标特征。
